## 验收中发现并修复

1. PE 字段表把 record 的合成属性 `EqualityContract` 和一个计算属性当成存储列。
   修复：`ModelBuilder.ScanMembers` 只收存在 `<Name>k__BackingField` 的属性；计算属性仍可作为信号，
   但不再进入类型布局。
2. ER 表把未知布局显示成 0/0。修复：`size = 0` 时偏移与大小显示「—」；`size = 0` 是既有的
   「未知」约定（`ArtifactType.size` 同义）。
3. 勾选信号后画布被无条件滚到最右（`scrollLeft = scrollWidth`），勾中的信号与写函数全部滚出视野，
   229px 的左栏里只剩读函数残片。修复：`revealNode()` 按被操作的条目定位——节点已可见则不动，
   窄于视口居中、宽于视口左对齐；模块/分组勾选回到读图起点；ER 字段反查也复用同一逻辑。
4. 节点文字按字符数截断（22/30 字符），中文全角在 200px 节点里仍会溢出，信号副标题压到下一列的
   「读」标签上。修复：`fitText()` 用 `canvas.measureText` 按实际渲染宽度二分截断并补省略号，
   主标签可用 156px、副标题 182px（右侧留 10px 内边距）。

## 四次改进核对：多级分组、配置持久化与工具栏收纳（2026-10-21）

触发：用户要求分组模式支持“依次添加多层级属性、每层在树里生成属性值桶、模块挂到桶下”，
分组条件能起别名、保存、设默认，并持久化到产物同目录的 `.drawcode.json`；产物或配置变化
导致属性失效时不能异常。随后追加：上方分组 / 筛选区域要有展开与收纳两种形态，默认收纳，
收纳态只占一行关键操作；验证不能只看 C# 产物，C 的 `.o/.out/.a/.so` 也要验。

### 实现要点

| 能力 | 实现 |
| :--- | :--- |
| 多级分组 | 每层属性生成一组桶行；模块按属性值挂到桶下；同一模块多值会在多条路径出现，行键带出现路径保证唯一 |
| 桶行 | `kind:"bucket"`，记录层级、属性值、路径、模块/端口集合；未标注值用 `（未标注）` 兜底 |
| 折叠锚定 | 每条出现链记录「桶 → 模块 → I/O 分组」行键；折叠时取链上最深的可见行作为端点 |
| 配置持久化 | 宿主原子写 `<产物 basename>.drawcode.json`（临时文件 + rename）；路径只由 `document.uri` 推导，webview 不能指定路径 |
| 别名 / 默认 | `presets[{alias, levels}]`、`active`、`defaultPreset`；首次打开按 会话别名 → 默认别名 → 上次层级 解析 |
| 失效降级 | 未知属性保留在配置里，分组时落入「（未标注）」并提示；坏 JSON / 读写失败只产生 warning，不抛异常 |
| 工具栏两态 | 收纳态只留「筛选与分组」开关、搜索框、属性筛选、分组开关与分组摘要（实测一行 34px）；展开态显示全部开关、批量展开与分组配置条（59px） |

### 边界与遗留

- 配置文件名只取 basename，因此 `libapp.a` 与 `libapp.so` 会共用同一个

- 分组会让同一模块按属性值重复出现，树行数可能远大于普通树（该样本 101 → 838）；

- C 产物为复制到临时目录后验证，避免在 `templates/` 里生成 `.drawcode.json`。

## 六次改进核对：活动栏产物树（2026-10-21）

触发：用户要求像 Mermaid Preview / 解决方案资源管理器那样，在 VS Code 左侧
活动栏提供「产物树」入口；可建多棵多层树，把产物挂到任意节点并设置别名，
点击产物打开浏览界面，树随工作空间持久化。

### 实现

| 能力 | 实现 |
| :--- | :--- |
| 活动栏入口 | `viewsContainers.activitybar` 新增 `drawcode` 容器，`views` 注册 `drawcode.artifactTrees`，图标 `media/artifacts.svg` |
| 数据模型 | `src/tree/model.ts` 纯数据层：`tree` / `folder` / `artifact` 三类节点，所有写操作返回新 store |
| 持久化 | `context.workspaceState` 的 `drawcode.artifactTrees.v1`；串行写入，坏数据清洗后降级，不抛异常 |
| 增删改 | 新建树、新建分组、添加产物、扫描工作空间、加入当前产物、重命名/别名、移除；标题栏与右键菜单共用命令 |
| 打开 | 产物节点 `command = drawcode.tree.openArtifact`，内部执行 `vscode.openWith(uri, drawcode.artifact)` |
| 拖拽 | `TreeDragAndDropController`：内部 MIME 只传节点 id，外部 `text/uri-list` 接收资源管理器文件；拖到产物上落到其父容器 |
| 安全边界 | 树根不可拖成子节点；禁止拖到自身或后代；深度、节点数、子节点数、名称长度均有限制 |

### 真实安装核对

隔离实例（`--user-data-dir` / `--extensions-dir` 指向临时目录）安装
`drawcode-artifact-viewer-0.2.0.vsix` 后重载窗口：

| 核对点 | 结果 |
| :--- | :--- |
| 活动栏入口 | 「Drawcode 产物」图标出现在资源管理器、搜索等图标之后；点击后侧边栏标题为「Drawcode 产物: 产物树」 |
| 新建树 | 欢迎页「新建产物树」→ 输入「示例产物」→ 树根出现，描述「0 个产物」 |
| 加入当前产物 | 自定义编辑器为活动标签时执行「将当前产物加入产物树」→ 选择目标树 → 别名「样本产物」→ 树根变「1 个产物」 |

### 边界

- 产物树存在 `workspaceState`，不写仓库文件；换工作空间是另一套树。
- 拖拽核对用页面内合成 `DragEvent` 走 VS Code 的树 DnD 管线，不是人手鼠标操作；
  工作台普通鼠标点击用 DOM `mousedown/mouseup/click` 同步事件验证，`Input.dispatchMouseEvent`
  在 webview 持有焦点时不改树选中态。
- 产物路径失效时节点显示警告图标，点击给「仍然尝试 / 从树中移除」，不会自动删除。
- 顶层树不允许拖入其他树；树内可任意换层级，深度上限 12。
