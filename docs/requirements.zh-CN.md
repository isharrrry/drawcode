# 需求与验收标准

[English](requirements.md) | **中文**

> **drawcode** 的需求契约：产品承诺什么、每条承诺如何从外部判定，以及某条承诺改变时其它文档必须同步什么。

## 本文档的地位

本文档是需求与验收的权威来源。其余文档 —— 架构、注解、`.drawio` 格式、程序集产物格式、模板与扩展说明 —— 解释这些需求**如何**被满足，写给实现者与使用者。本文档与其中任何一份冲突时，**以本文档为准**，那一份是错的，必须改正。

未写在这里的行为**不构成承诺**。某些能力可能存在、被别处记录、有测试覆盖，却没有出现在本文档中；那意味着它们是附带实现，不是契约。凡刻意不作承诺的项目列在[§6](#6-推迟与排除)，而不是留成含糊地带。

## 阅读约定

| 术语 | 含义 |
| :--- | :--- |
| **SHALL** / **MUST** | 强制。偏离即为缺陷，不是偏好。 |
| **MUST NOT** | 禁止。禁令是契约的一部分，不是建议。 |
| **MAY** | 允许但可选。不具备该行为不算缺陷。 |
| **SHOULD** | 推荐。仅在偏离处写明理由时才可偏离。 |
| **REQ-\<DOMAIN\>-NN** | 一条需求。**NN** 为两位数字，从 `01` 起在本域内连续。域清单见[§3](#3-需求)。 |
| **AC-\<DOMAIN\>-NN.M** | 一条验收判据，归属于 `NN` 相同的需求。**M** 从 `1` 起。每条需求至少有一条。 |
| **WHEN … THEN …** | 判据从产品**外部**判定：一次用户操作、一个输入文件，或一个无需检视内部即可观察到的输出。 |

**判据如何判定为失效。** 当一名观察者只依照的 **WHEN** 子句行事，就能看到 **THEN** 子句不成立时 —— 依据产品公开面（命令行调用、编辑器、被写出的文件、被打印的诊断）—— 该判据失效。判据**不因动机而豁免**：用错误的理由得出正确答案的实现并未满足它；内部看起来正确、可观察输出不同的实现则已失效。

判据**不因**某个尚未测量的实现细节而放宽。若今天产不出该可观察行为，正确做法是把这条承诺移进[§6](#6-推迟与排除)，绝不在本文档里软化措辞。

## 1. 产品意图

1. **实现本身必须携带系统摘要。** 由带注解的源码构建出的程序集，同时是一个可运行的程序，和一份关于模块如何交联、信号如何流动、哪些数据是持久化的、哪些模块是分解根的结构化陈述。该摘要不是由人另行维护的独立产物，它随构建一起走。
2. **只有一个事实源。** 源码文本就是那个事实源。系统的任何中间表示都从不写入磁盘：它只存在于内存中，每次运行重新构建。必须与代码保持同步的设计文档，正是本产品要消灭的失效。
3. **反向方向刻意收窄。** 写回源码仅限于声明层 —— 方向、元数据，以及被人为钉住的坐标。函数体永不重写，因为图是低保真视图，任何从图重建逻辑的工具都是在源码文件里猜。
4. **布局是人的决定，属于图。** 坐标不参与编译，且是本系统中唯一无法从代码重新生成的东西。因此它住在图里，由拖拽产生，在下一次运行时被读回。
5. **交付出的二进制必须可读而无需运行。** 可以从一个编译产物中静态读出同样的结构，不执行、不动态加载、不做被检程序的依赖解析。

## 2. 范围与非目标

### 范围内

| 领域 | 承诺什么 |
| :--- | :--- |
| **源码摄取** | 解析带注解的 C 与 C# 源码，得到模块、信号、函数、参数、设备与读写边的内存模型。 |
| **图生成** | 产出合法的 `.drawio` 文件，以确定的默认布局与避障正交路由表达该模型。 |
| **布局往返** | 从 `.drawio` 读回布局与少数允许人工编辑的属性，包括 draw.io 默认写出的压缩存储形态。 |
| **声明层写回** | 按图重写源码中的注解块，不动其它任何内容。 |
| **注解体系** | 定义提供方向、元数据、设备数据、自由文本与几何覆盖的键与特性。 |
| **元数据模板** | 提供可直接复制的 C# 特性定义与 C 宏记录，在常见链接、strip 与裁剪选项下仍然存活。 |
| **编译产物读取** | 静态读取 PE/CLI、ELF 与 `ar` 产物，得到有文档的模型、稳定标识与诊断，并输出规范 JSON。 |
| **编辑器集成** | 只读的 VS Code 程序集编辑器、程序集树、导出路径，以及从资源管理器生成源码图。 |
| **可移植性** | 一条无第三方运行时依赖的命令行工具链，与一个在 Windows 和 Linux 上通用的扩展包。 |
| **验证纪律** | 覆盖模型与几何的冻结金标准契约，以及「每个公开数字都来自实测」的规则。 |

### 范围外

| 不作承诺 | 理由 |
| :--- | :--- |
| 从产物反编译、反汇编或重建源码 | 产物路径产出的是结构摘要；把机器码或 IL 变回可读代码是另一款产品，有不同的保证。 |
| 把产物反向转译为源码或 `.drawio` | 产物没有可写入的声明层，也没有可标注的源码；造一个出来就是在制造无法验证的源码。 |
| 状态机、时序图、时序（timing）图，以及多页图或分层图 | 本产品建模的交互流是模块交联与信号读写路径；其余几类需要一个它并不具备的语义层。 |
| 跨程序集与跨语言的符号解析 | 跨语言或跨程序集连接名称需要输入并不携带的整程序知识，且框架调用带来的噪声会淹没信号。 |
| MSVC 目标、对带元数据单元的链接时优化、`.dylib`、`.exe` 与 `.pdb` 支持 | 元数据布局与段保留保证是为 GCC/Clang 的 ELF 目标与 PE/CLI 元数据定义的；其余语义不同，未覆盖。 |
| 需求追溯、验证用例或参数分析 | 这些属于具备语义栈的建模语言；本产品建模的是实现结构，不是需求。 |
| 在两次运行之间持久化中间模型 | 第二份被持久化的语义表示正是本产品为消除漂移而设计要排除的东西。 |

## 3. 需求

### SRC —— 源码摄取

#### REQ-SRC-01  把 C 及 C 家族源码解析进模型

**Requirement.** 工具 SHALL 解析 C 及 C 家族源码文件 —— 至少 `.c`、`.h`、`.cpp`、`.hpp`、`.cc` 与 `.hh` —— 并 SHALL 解析 C# 文件（`.cs`）。单次调用 MUST 接受这些语言的任意混合输入并产出一份模型。

**Rationale.** 采用方已经在这些语言里有源码；要求先重写才能读出任何东西，正是本产品要消除的采用成本。

**Acceptance criteria.**

- **AC-SRC-01.1** —— **WHEN** 一组 C 头文件与实现文件被传给工具，**THEN** 产出的图为那些文件中的每一个带注解的信号与每一个被识别的函数都包含一个节点。
- **AC-SRC-01.2** —— **WHEN** 一个 `.cs` 文件与 C 文件一同传入，**THEN** 产出一张图，同时含两种语言的实体，且不报「混合语言」错误。
- **AC-SRC-01.3** —— **WHEN** 传入一个扩展名不受支持的文件，**THEN** 工具把该文件报为不支持，且不因它而使整次运行失败。

**Evidence.** 解析层金标准比对（L1 层）；见《Conformance》与《Examples》。

#### REQ-SRC-02  只有带注解的顶层声明才是信号

**Requirement.** 工具 SHALL 仅在顶层变量带有 drawcode 注解时才将其视为信号。未带注解的顶层变量 MUST NOT 成为信号，无论其类型、链接性或拼写如何。数组声明符 SHALL 折叠进类型串，而不是每个元素产出一个实体。

**Rationale.** 信号是图的词汇表。仅凭语法推断会使图被无关全局量淹没而不可读；注解是作者对「该值跨越模块边界」的明确声明。

**Acceptance criteria.**

- **AC-SRC-02.1** —— **WHEN** 一个源文件含一个带注解与一个未带注解的顶层变量，**THEN** 其中恰好一个作为信号出现。
- **AC-SRC-02.2** —— **WHEN** 一个信号声明为 `float g_coeff[32];`，**THEN** 产出一个信号，其类型读作 `float[32]`。
- **AC-SRC-02.3** —— **WHEN** 注解挂在一个不是顶层变量的构造上，**THEN** 不为其产出任何信号。

**Evidence.** 信号键参考与其示例；见《Annotations》。

#### REQ-SRC-03  函数按形态识别，不依赖注解

**Requirement.** 工具 SHALL 依据声明形态识别函数，而不要求注解。控制关键字与非声明语句 MUST NOT 被误认为函数。未带注解的函数 SHALL 仍然成为一个节点，只是没有任何别名。

**Rationale.** 边来自函数体，漏掉一个函数就静默丢失数据流。按形态识别保证模型完整，而注解始终是可选的装饰。

**Acceptance criteria.**

- **AC-SRC-03.1** —— **WHEN** 一个源文件定义了一个其上方没有注解的函数，**THEN** 图中包含一个以该函数真实名称标注的节点。
- **AC-SRC-03.2** —— **WHEN** 一个源文件含 `if`、`for`、`while`、`switch` 或 `return` 之类控制语句，**THEN** 其中任何一条都不成为函数节点。

**Evidence.** 函数层面的 L1 金标准比对；见《Conformance》。

#### REQ-SRC-04  读写边由函数体派生

**Requirement.** 工具 SHALL 在剥离注释后扫描函数体对已声明信号的访问，据此派生 `read` 与 `write` 边。复合赋值 SHALL 同时算作对其左操作数的一次读与一次写。无法解析到已声明信号的标识符 MUST NOT 产生边。工具 MUST NOT 依据注解产生边。

**Rationale.** 函数体才是真相所在。从文本派生边使图不会退化成一份手工维护的平行描述，这也正是一条注释能改标签却永不能移动一行的原因。

**Acceptance criteria.**

- **AC-SRC-04.1** —— **WHEN** 一个函数体向某已声明信号赋值，**THEN** 一条 `write` 边从该函数指向该信号。
- **AC-SRC-04.2** —— **WHEN** 一个函数体读取某已声明信号，**THEN** 一条 `read` 边从该信号指向该函数。
- **AC-SRC-04.3** —— **WHEN** 一个信号带注解但没有任何函数体触及它，**THEN** 不为其产生边。
- **AC-SRC-04.4** —— **WHEN** 一个局部变量或参数与任何已声明信号同名，**THEN** 不为其产生边。

**Evidence.** 模型层金标准用例中的边派生断言；见《Annotations》与《Conformance》。

#### REQ-SRC-05  多输入合并而不做符号解析

**Requirement.** 工具 SHALL 以实体拼接的方式把若干输入文件合并为一份模型。同一名称出现在多处声明时，工具 SHOULD 优先采用头文件声明的注解。MUST NOT 尝试跨语言名称解析。

**Rationale.** 拼接式合并可预测，且不需要「整个程序」的概念。跨语言解析需要一套横跨两种语言的类型系统，而输入并不提供。

**Acceptance criteria.**

- **AC-SRC-05.1** —— **WHEN** 同一信号同时声明在头文件与实现文件中，**THEN** 头文件中的注解作用于合并后的那一个信号。
- **AC-SRC-05.2** —— **WHEN** 一个 C 文件与一个 C# 文件各自声明了同名信号，**THEN** 两者都存在于模型中，且不因同名而建立任何边。

**Evidence.** 与注解参考一同陈述的合并规则；见《Annotations》。

### SYNC —— 声明层写回

#### REQ-SYNC-01  只写回声明层

**Requirement.** 从图写回源码 SHALL 只修改属于某实体的注解块 —— 其方向键、元数据键、设备键，以及适用时的几何键。函数体 MUST NOT 被重写。实体注解块之外的代码 MUST 保持逐字节不变。

**Rationale.** 图知道一个函数读取某信号，但不知道循环边界、错误处理或算术。把写回限制在声明层，使该操作可证明是安全的：它只能触碰图完整表达其内容的那几行。

**Acceptance criteria.**

- **AC-SYNC-01.1** —— **WHEN** 在图里改掉某实体的别名并写回，**THEN** 注解块反映新别名，且函数体逐字节未变。
- **AC-SYNC-01.2** —— **WHEN** 一个源文件在注解块之外有语句、注释与格式，**THEN** 它们都不因写回而改变。

**Evidence.** 写回规则及其「其它代码未受影响」断言；见《Annotations》。

#### REQ-SYNC-02  写回需要显式授权

**Requirement.** 一次写回运行 SHALL 默认是空跑：报告将发生的变化，不修改任何文件。只有在调用方明确要求时才写出文件。

**Rationale.** 会意外重写源码的工具在受版本控制的仓库里无法使用。要求显式开关使默认行为保持安全。

**Acceptance criteria.**

- **AC-SYNC-02.1** —— **WHEN** 未带写授权调用写回，**THEN** 工具报告预期的变化，且没有任何文件的修改时间改变。
- **AC-SYNC-02.2** —— **WHEN** 同一调用带上写授权重复执行，**THEN** 所报告的变化被写入。

**Evidence.** 与命令参考一同记录的命令行行为；见《Implementation》。

#### REQ-SYNC-03  合并在键级进行，而非行级

**Requirement.** 写回注解块时，工具 SHALL 保留它不管理的键与特性 —— 包括手写的那些 —— 的位置、顺序与写法，并 SHALL 只重写取值确实发生变化的键。

**Rationale.** 用户会手工定制注解块 —— 加一段样式片段、紧凑书写单位、在特性上方留一行设备数据。整块替换会静默删掉这些工作。

**Acceptance criteria.**

- **AC-SYNC-03.1** —— **WHEN** 某注解块含一个工具不管理的手写键，**THEN** 该键在写回后原样保留。
- **AC-SYNC-03.2** —— **WHEN** 一个多属性实体只有一个属性变化，**THEN** 其它属性不会被改写成另一种写法。

**Evidence.** 参数级合并规则；见《Annotations》。

#### REQ-SYNC-04  无落差即无改动

**Requirement.** 工具 SHALL 只对那些图上的几何与其构建本应产出的几何不同的实体写入几何键。源码已经钉住自身几何的实体 MUST NOT 被改写成同一数值的另一种写法。一次写回运行之后，未被改动过的工程 SHALL 产出逐字节相同的源文件。

**Rationale.** 这正是反向方向得以幂等的原因，也使一次无关的编辑不会在 diff 里制造坐标噪声。

**Acceptance criteria.**

- **AC-SYNC-04.1** —— **WHEN** 依次执行构建、写回、构建且期间不做任何编辑，**THEN** 源文件与其原始状态逐字节相同。
- **AC-SYNC-04.2** —— **WHEN** 在图里拖动一个节点并写回，**THEN** 只有该实体新增或更新几何键。

**Evidence.** 往返幂等主张及其测量；见《Verification》。

### IR —— 模型与默认布局

#### REQ-IR-01  中间模型从不持久化

**Requirement.** 模型 SHALL 仅在一次运行的持续期内存在于内存。工具 MUST NOT 把它作为交换产物写入磁盘，也 MUST NOT 要求以它为输入。每次运行 SHALL 从源码文本重新构建模型。

**Rationale.** 持久化语义会造出第二个事实源，进而被迫引入哈希、漂移检测与三方合并。唯一持久的载体是源码与图。

**Acceptance criteria.**

- **AC-IR-01.1** —— **WHEN** 一次构建运行结束，**THEN** 它创建的文件只有用户所要求的那些；旁边不出现模型文件或交换文件。
- **AC-IR-01.2** —— **WHEN** 两次运行之间源码被编辑，**THEN** 第二次运行反映该编辑，且无需任何迁移或缓存失效步骤。

**Evidence.** 分层决策与持久层表；见《Architecture》。

#### REQ-IR-02  边只有一个生产者

**Requirement.** 所有 `read` 与 `write` 边 SHALL 由对函数体的同一次派生产生。任何其它子系统都 MAY NOT 增加、删除或改变一条边的类别。

**Rationale.** 单一生产者才是「图不可能与代码漂移」成立的原因，而不是一句愿望。两个生产者就需要冲突规则，而冲突规则又需要合并。

**Acceptance criteria.**

- **AC-IR-02.1** —— **WHEN** 某信号的注解方向被改变，**THEN** 与该信号相关的边集合不变。
- **AC-IR-02.2** —— **WHEN** 一条读取或写入某信号的语句从函数体中被删除，**THEN** 对应的边消失。

**Evidence.** 「注解不控制边」的规则；见《Annotations》。

#### REQ-IR-03  默认布局是确定的

**Requirement.** 在不存在既有布局时，工具 SHALL 以固定规则计算位置与尺寸。同一输入 SHALL 在每次运行、每台机器上产出相同几何，不依赖文件系统遍历顺序、哈希顺序或挂钟时间。

**Rationale.** 确定性使几何得以逐字节比对，而逐字节比对使一次布局回归表现为可评审的差异，而不是看不见的漂移。

**Acceptance criteria.**

- **AC-IR-03.1** —— **WHEN** 同一输入被构建两次，**THEN** 产出的图文件逐字节相同。
- **AC-IR-03.2** —— **WHEN** 输入被复制到另一个目录后构建，**THEN** 节点几何相同。

**Evidence.** 已提交几何金标准的字节相等性；见《Conformance》。

### DRAWIO —— 图文件契约

#### REQ-DRAWIO-01  生成文件满足 draw.io 文档骨架

**Requirement.** 工具 SHALL 产出 `.drawio` 文档，其中包含图容器、一个默认图层，以及架构所要求的根单元。生成文件 SHALL 通过随工具分发的 draw.io 文件架构校验。

**Rationale.** 一个 draw.io 打不开的文件比没有文件更糟，而架构合法性是防止一个细微畸形的文档流到用户手上最廉价的手段。

**Acceptance criteria.**

- **AC-DRAWIO-01.1** —— **WHEN** 一个生成文件接受架构校验，**THEN** 校验通过。
- **AC-DRAWIO-01.2** —— **WHEN** 一个生成文件在 draw.io 中打开，**THEN** 图以容器、节点与边正确渲染。

**Evidence.** 架构层比对（L4 层）；见《Conformance》。

#### REQ-DRAWIO-02  节点以属性承载语义载荷

**Requirement.** 每个节点与边 SHALL 以可承载自定义属性的形式产出，且 SHALL 至少包含一个与其模型实体相连的稳定标识、显示标签与实体类别。信号方向、类型、单位以及存在的人类可读注解值 SHALL 在存在时镜像为属性。

**Rationale.** 连接键使布局能在反复重建之间复用。没有它，图就是一张无从回溯其所描述之物的图。

**Acceptance criteria.**

- **AC-DRAWIO-02.1** —— **WHEN** 一个生成文件被检视，**THEN** 每个节点都携带一个可解析到模型实体的标识。
- **AC-DRAWIO-02.2** —— **WHEN** 某实体在源码中有别名、单位或说明，**THEN** 这些值作为属性出现在对应元素上。

**Evidence.** 元素映射与属性表；见《`.drawio` 格式》。

#### REQ-DRAWIO-03  形状编码方向

**Requirement.** 节点形状 SHALL 区分输入、输出与无方向的信号，并 SHALL 区分函数与信号。外部实体 SHALL 与本地实体在视觉上可区分。方向 MUST 能仅凭形状读出，而无需在节点之上另画标记。

**Rationale.** 关于数据流图最常见的问题是「这个往哪个方向流」；重复的标记会与标签争位置，而轮廓能前注意地直接回答。

**Acceptance criteria.**

- **AC-DRAWIO-03.1** —— **WHEN** 一个信号被标注为输入，**THEN** 其形状与被标注为输出的信号不同。
- **AC-DRAWIO-03.2** —— **WHEN** 某实体被标为外部，**THEN** 其呈现与同类本地形态不同。

**Evidence.** 节点样式表；见《`.drawio` 格式》。

#### REQ-DRAWIO-04  坐标父相对且双向可转换

**Requirement.** 节点坐标 SHALL 按格式要求相对于所属单元存储。工具 MUST 提供且仅提供一个与绝对画布坐标之间的转换点，且两个方向 MUST 互为精确逆运算。

**Rationale.** 两处转换点会在每次往返时漂移一点，而这点漂移会被归因于用户的拖拽，而不是工具。

**Acceptance criteria.**

- **AC-DRAWIO-04.1** —— **WHEN** 一次构建之后，用产出的布局再次构建，**THEN** 每个节点的绝对位置不变。
- **AC-DRAWIO-04.2** —— **WHEN** 两张图以不同嵌套深度描述同一批绝对位置，**THEN** 转换之后再比对不报告差异。

**Evidence.** 坐标语义一节与归一化规则；见《`.drawio` 格式》与《Conformance》。

#### REQ-DRAWIO-05  边绕开障碍路由

**Requirement.** 工具 SHALL 通过尝试一组固定的锚点组合与候选正交路径，丢弃任何与节点框相交的候选，并选取存活路径中最短的一条来路由每条边。当没有任何候选免于碰撞时，边 MUST 不带锚点属性发出，交由查看器自行路由 —— 而不是发出一个穿过节点的带锚点边。

**Rationale.** 连线穿过无关方框的图不可读；而一条穿过节点的带锚点边比不带锚点更糟，因为它错误地表示了作者所选的两端。

**Acceptance criteria.**

- **AC-DRAWIO-05.1** —— **WHEN** 分属不同容器的两个实体相连，**THEN** 发出的边没有任何线段穿过无关节点的框。
- **AC-DRAWIO-05.2** —— **WHEN** 多条边共享同一竖直区段，**THEN** 它们的弯折发生在不同位置，使每条线可被单独辨认。

**Evidence.** 路由规则与锚点组合表；见《`.drawio` 格式》。

#### REQ-DRAWIO-06  两种存储形态都必须可读

**Requirement.** 工具 SHALL 既能读取明文形态，也能读取 draw.io 保存时产出的压缩形态。压缩载荷 MUST 被透明展开，且得到的模型 SHALL 与同一内容的明文形态所得模型相同。

**Rationale.** draw.io 默认压缩。只处理明文的读取器会在用户第一次保存自己的排版时静默返回空布局，而这正是会丢失工作的失效。

**Acceptance criteria.**

- **AC-DRAWIO-06.1** —— **WHEN** 一份被 draw.io 以压缩形态保存的图被读取，**THEN** 节点数、边数与可读属性数与该内容的明文形态相同。
- **AC-DRAWIO-06.2** —— **WHEN** 一份图经 draw.io 保存后被重新读取，**THEN** 布局反映用户所做的排版，而不是默认排版。

**Evidence.** 压缩存储能力及其回读实测数字；见《Conformance》与《Verification》。

#### REQ-DRAWIO-07  不可读载荷载趾而明

**Requirement.** 当一份图的载荷无法展开时，工具 MUST 以诊断失败，且 MUST NOT 返回空布局。空布局专属于确实不含布局的图。

**Rationale.** 静默返回空与「这张图没有布局」无法区分，调用方会以默认值覆盖手工作品并报告成功。报错使损坏在失效点即被发现。

**Acceptance criteria.**

- **AC-DRAWIO-07.1** —— **WHEN** 某个图元素所含文本不是合法载荷，**THEN** 工具报错且不写出任何输出图。
- **AC-DRAWIO-07.2** —— **WHEN** 某个图元素为空，**THEN** 工具跳过它，且不把该文件视为损坏。

**Evidence.** 读取行为表与拒绝样本；见《`.drawio` 格式》与《Examples》。

#### REQ-DRAWIO-08  往返区分自动与人工拐点

**Requirement.** 读取一份由早先运行产出的图时，工具 SHALL 针对当前节点位置重新计算其路由本应发出的拐点，并 SHALL 丢弃与该重算结果相等的拐点，仅保留不同的那些。因此，期间无编辑的构建 MUST 产出相同文件，而被人拖动的边 SHALL 在后续构建中保持其路径。

**Rationale.** 生成器把拐点写进人也会编辑的同一份文件，因此它无法依赖标记或独立存储。与重算结果比对是同时满足这两个性质的唯一办法。

**Acceptance criteria.**

- **AC-DRAWIO-08.1** —— **WHEN** 一份图在无编辑情况下构建两次，**THEN** 第二个文件与第一个逐字节相同。
- **AC-DRAWIO-08.2** —— **WHEN** 一条边的线路被人为移动后重建该图，**THEN** 该边保持被移动后的路径，而其它边按其节点位置重新路由。

**Evidence.** 往返表与幂等测量；见《`.drawio` 格式》与《Verification》。

### ANN —— 注解体系

#### REQ-ANN-01  C 注解是键值注释块

**Requirement.** 在 C 中，注解 SHALL 是紧贴声明之上的一段连续 `///` 行，在标签之后承载 `key="value"` 对。键 SHALL 为裸词，值 SHALL 以双引号包围，且值 MUST NOT 含双引号。空行 SHALL 终止该块。未知键 MUST 被忽略而非拒绝。

**Rationale.** 邻近性加按行语法使注解读起来仍是注释，且无需预处理器、包含文件或构建步骤。

**Acceptance criteria.**

- **AC-ANN-01.1** —— **WHEN** 一个声明前有带方向键的注解块，**THEN** 该实体携带该方向。
- **AC-ANN-01.2** —— **WHEN** 空行把注解块与声明隔开，**THEN** 该注解不生效。
- **AC-ANN-01.3** —— **WHEN** 该块含工具不认识的键，**THEN** 运行成功且该键被忽略。

**Evidence.** 注解语法一节及其识别约束；见《Annotations》。

#### REQ-ANN-02  C# 注解是向前绑定的特性

**Requirement.** 在 C# 中，注解 SHALL 是施加于其所记录声明上的特性。工具 SHALL 把特性绑定到下一个字段、属性或方法声明，跳过空行、using 指令、命名空间声明、预处理行与单独的括号。方向参数 MAY 省略，此时该实体被记录但没有方向。

**Rationale.** 特性是语言自身的机制，因此拼错属性名会在编译期失败而不是被静默忽略 —— 这比注释能给出的保证更强。

**Acceptance criteria.**

- **AC-ANN-02.1** —— **WHEN** 特性与其目标之间隔着空行或 using 指令，**THEN** 它仍然绑定到该目标。
- **AC-ANN-02.2** —— **WHEN** 特性只带元数据而不带方向，**THEN** 该实体以空方向出现。

**Evidence.** 特性绑定规则；见《Annotations》。

#### REQ-ANN-03  方向原样映射，从不纠正

**Requirement.** 工具 SHALL 把声明出的方向原样映射进模型。在模板定义枚举的情况下，`None` SHALL 映射为无方向、`In` 映射为输入、`Out` 映射为输出、`Io` 映射为双向，且工具 MUST NOT 为使它符合另一种直觉而互换这些含义。

**Rationale.** 模板的注释把方向定义为相对于模块。在读取时「纠正」它，会把视图里的每个箭头相对源码图翻转，而产生的两张自相矛盾的图比一个反直觉的定义更糟。

**Acceptance criteria.**

- **AC-ANN-03.1** —— **WHEN** 一个信号以输入方向声明，**THEN** 模型记录为输入，视图把它渲染为输入端口。
- **AC-ANN-03.2** —— **WHEN** 一个产物与其源码各按自身路径被读取，**THEN** 同一信号的方向在两者之间一致。

**Evidence.** 两种语言各自的方向映射表；见《Annotations》与《Artifact format》。

#### REQ-ANN-04  任何注解都不影响边集合

**Requirement.** 增加、修改或删除一条注解 MUST NOT 增加、删除、改变类别或改向任何一条边。只有对函数体的改动 MAY 做到。

**Rationale.** 这是「函数体即真相」的可观察形态。没有它，注释就成为一种凭空制造结构的手段，图也不再是派生物。

**Acceptance criteria.**

- **AC-ANN-04.1** —— **WHEN** 一个信号的方向从输入改为输出，**THEN** 与其相关的边在集合、方向与数量上均不变。
- **AC-ANN-04.2** —— **WHEN** 一条注解被整体删除，**THEN** 相关边仍在，只有标签改变。

**Evidence.** 「为何注解不控制边」一节；见《Annotations》。

#### REQ-ANN-05  未知键被忽略以保持前向兼容

**Requirement.** 工具不认识的键或特性 MUST 在两种语言中都被忽略而非拒绝。已识别几何键的畸形取值 MUST NOT 中止运行。

**Rationale.** 旧读取器必须仍能消费更新的注解，否则词汇表每扩展一次就会打断既有的工具链。忽略也正是让同一份源码可被多个版本的工具读取的原因。

**Acceptance criteria.**

- **AC-ANN-05.1** —— **WHEN** 源码带有由更新词汇表引入的键，**THEN** 运行成功且所有已识别的键均生效。
- **AC-ANN-05.2** —— **WHEN** 某几何键的取值无法解释为数值，**THEN** 运行完成而不中止。

**Evidence.** 前向兼容声明与几何键规则；见《Annotations》与《Conformance》。

#### REQ-ANN-06  几何键按实体覆盖默认布局

**Requirement.** 信号与函数 SHALL 都接受钉住该实体绝对位置、初始尺寸与样式片段的键，其中样式片段 SHALL 逐字附加到该实体的渲染样式之后。缺失或空值 MUST 保持默认不变。该片段 MUST 在写回中存活，因为工具不管理它。

**Rationale.** 有些节点的意义来自位置 —— 一块图例区、一列镜像物理机架的堆叠。允许作者钉住它们，使默认布局对其它一切仍然有用。

**Acceptance criteria.**

- **AC-ANN-06.1** —— **WHEN** 某实体带位置键，**THEN** 生成的图把它放在该位置而不是默认堆叠位置。
- **AC-ANN-06.2** —— **WHEN** 某实体的几何键取值为空，**THEN** 输出与不带该键的输出逐字节相同。
- **AC-ANN-06.3** —— **WHEN** 某实体带样式片段，**THEN** 写回保留该片段。

**Evidence.** 几何键参考与写回表；见《Annotations》。

#### REQ-ANN-07  自由文本块独立于其宿主声明

**Requirement.** 工具 SHALL 支持自由文本块，携带文字、绝对坐标、尺寸与视觉种类（无边框文字、着色方框或宽幅条带）。文本块的位置 SHALL 来自它自己的坐标，且 MUST NOT 依赖它所书写于其上的实体。一个声明 MAY 挂多个文本块。

**Rationale.** 注解键装饰的是已经存在的实体，它们无法新增一个标题、一块图例，或一句说明「本图刻意省略了什么」的话。需要独立构造，而把它的位置绑到无关宿主会使它在排版上无法使用。

**Acceptance criteria.**

- **AC-ANN-07.1** —— **WHEN** 一个文本块带坐标，**THEN** 它出现在该坐标处，与其宿主实体的落点无关。
- **AC-ANN-07.2** —— **WHEN** 多个文本块挂在一个声明上，**THEN** 它们全部出现。
- **AC-ANN-07.3** —— **WHEN** 文本块指定了无法识别的视觉种类，**THEN** 它以纯文本渲染而不是被丢弃。

**Evidence.** 自由文本块参考；见《Annotations》。

### TPL —— 元数据模板

#### REQ-TPL-01  模板是一个自包含文件夹

**Requirement.** 每套模板 SHALL 只需把文件复制进工程即可使用，不需要包管理器步骤、代码生成器或构建脚本改动。C 模板 SHALL 在符合规范的 C 编译器下编译且其布局断言保持；C# 模板 SHALL 在无额外包引用的前提下编译。

**Rationale.** 整个产品的采用成本就是一个复制文件和几行注解。需要工具的模板会把本产品要消除的集成工程重新引入。

**Acceptance criteria.**

- **AC-TPL-01.1** —— **WHEN** C# 模板被复制进一个本来为空的工程并构建，**THEN** 构建成功且无额外包引用。
- **AC-TPL-01.2** —— **WHEN** C 模板被复制进工程并编译，**THEN** 编译期尺寸断言通过。

**Evidence.** 模板指南中的接入与验证一节；见《Templates》。

#### REQ-TPL-02  C# 特性保持源兼容

**Requirement.** C# 模板 SHALL 保留其特性既有的位置参数顺序与含义，并 MAY 增加可选命名参数以表达标签、持久化与树根。针对早期版本编写的源码 MUST 继续编译并产出相同元数据。

**Rationale.** 一个一扩展就中断的注解词汇表，会迫使每个采用方为一项他们并未要求的变更全面复审源码。

**Acceptance criteria.**

- **AC-TPL-02.1** —— **WHEN** 只用原始位置参数的既有源码针对当前模板编译，**THEN** 它编译通过并产出与之前相同的方向、单位与别名。
- **AC-TPL-02.2** —— **WHEN** 某成员带可选标签参数注解，**THEN** 标签可从产物中读出。

**Evidence.** 特性参数表；见《Templates》。

#### REQ-TPL-03  两种语言都能表达根与排除

**Requirement.** 词汇表 SHALL 允许作者把某实体标为分解根，并允许作者默认隐藏某实体。两者 SHALL 可从产物中读出。C 侧 SHALL 以保留标签表达同一语义。

**Rationale.** 大型系统的模块多过一张可读的默认视图所能容纳。根与排除让作者决定图显示什么，而不必从模型中删除任何东西。

**Acceptance criteria.**

- **AC-TPL-03.1** —— **WHEN** 某实体被标为根，**THEN** 查看器的默认视图列出它，且模型中存在对应标记。
- **AC-TPL-03.2** —— **WHEN** 某实体被标为排除，**THEN** 它默认隐藏，并在打开排除开关后可见。
- **AC-TPL-03.3** —— **WHEN** 在 C 中使用等价的保留标签，**THEN** 模型中呈现相同标记。

**Evidence.** 参数表中的根与排除两行；见《Templates》。

#### REQ-TPL-04  C 记录定长且无指针

**Requirement.** C 元数据记录 SHALL 是固定尺寸的纯数据结构，不含指针成员，且字符串字段 SHALL 为定长内联数组。记录尺寸的变化 MUST 在编译期失败，而不是静默地以旧布局误解释既有产物。

**Rationale.** 内联字符串是未链接目标文件可在无重定位的情况下被读取、以及 strip 无害的原因。指针会要求读取器解析一个已无意义的地址。

**Acceptance criteria.**

- **AC-TPL-04.1** —— **WHEN** 记录的字段布局被改动以致其尺寸不同于声明值，**THEN** 编译失败。
- **AC-TPL-04.2** —— **WHEN** 一个未链接的目标文件被检视，**THEN** 字符串字段在未施加重定位的情况下可读。

**Evidence.** 记录布局及其约束；见《Artifact format》与《Templates》。

#### REQ-TPL-05  元数据段在裁剪与 strip 后仍存活

**Requirement.** 模板 SHALL 以其记录能存活链接器段回收与 strip 的方式写出记录。模板文档 SHALL 描述保留手段，以及不支持该手段的工具链的退路。

**Rationale.** 在一个常见优化开关下消失的元数据，会把一个正常工作的配置变成空白视图且不报错，而失效点离其原因很远。

**Acceptance criteria.**

- **AC-TPL-05.1** —— **WHEN** 一个二进制在开启段回收的情况下被链接，**THEN** 全部元数据记录仍可读。
- **AC-TPL-05.2** —— **WHEN** 一个二进制被剥除全部符号，**THEN** 记录数量与内容不变。

**Evidence.** 段保留一节；见《Templates》。

#### REQ-TPL-06  元数据携带读取器可判读的版本

**Requirement.** 模板 SHALL 把版本标识写入产物，读取器 SHALL 将其与自身支持的版本比较。不受支持的版本 MUST 产生一条诊断并停止解码，而不是以错误的布局去解释。

**Rationale.** 记录布局终将改变。版本戳让旧读取器能说「这是更新的工具写的」，而不是产出一堆看似合理的胡话。

**Acceptance criteria.**

- **AC-TPL-06.1** —— **WHEN** 读取一份由该模板产出的产物，**THEN** 报告的元数据版本与模板声明一致。
- **AC-TPL-06.2** —— **WHEN** 一份产物声明了读取器不支持的版本，**THEN** 报告错误诊断，且不从该段解码任何实体。

**Evidence.** 产物 IR 中关于版本的需求及其场景；见《Artifact format》。

### ARTIFACT —— 编译产物读取

#### REQ-ARTIFACT-01  格式由内容决定，而非扩展名

**Requirement.** 读取器 SHALL 依文件前导字节识别格式。识别 SHALL 覆盖 `ar` 归档、PE 映像与 ELF 映像。字节不匹配任何一者的文件 MUST 被报为未知格式并产生错误诊断，且 MUST NOT 被当作其中任何一种读取。

**Rationale.** 一个 `.dll` 可能装的是本机代码，一个 ELF 可能被命名为 `.so` 或 `.out`，而 `ar` 归档里装的又是另一种格式的成员。信任扩展名会误解析正确的输入，更糟的是接受错误的输入。

**Acceptance criteria.**

- **AC-ARTIFACT-01.1** —— **WHEN** 一个以 PE 扩展名命名、内容却是 ELF 字节的文件被读取，**THEN** 它按 ELF 解析且不报格式错误。
- **AC-ARTIFACT-01.2** —— **WHEN** 一个扩展名看似合理、内容为不可识别字节的文件被读取，**THEN** 结果报告未知格式并带错误诊断，且无未捕获的失败。

**Evidence.** 支持的输入表与分派场景；见《Artifact format》。

#### REQ-ARTIFACT-02  PE/CLI 产物静态读取

**Requirement.** 从携带 CLI 元数据的产物中，读取器 SHALL 产出模块、类型、信号、函数与读写边，包括位置记录字段与参数数据。它 MUST NOT 加载目标程序集、解析其依赖，或执行其任何代码，包括静态构造函数与模块初始化器。

**Rationale.** 检视一个产物必须与看它一样安全。任何加载映像的代码路径都会运行初始化器，那么一份来自供应商的二进制，仅因为被打开就会在评审者机器上执行。

**Acceptance criteria.**

- **AC-ARTIFACT-02.1** —— **WHEN** 检视一个其带注解字段被某方法读写的产物，**THEN** 该信号携带声明的方向、单位与别名，且该函数同时携带一条读边与一条写边。
- **AC-ARTIFACT-02.2** —— **WHEN** 产物声明了静态构造函数或模块初始化器，**THEN** 检视它产出一份模型且不产生任何副作用。
- **AC-ARTIFACT-02.3** —— **WHEN** 某方法调用框架或第三方程序集的成员，**THEN** 不为该调用建立函数节点或边。

**Evidence.** PE/CLI 需求及其场景；见《Artifact format》。

#### REQ-ARTIFACT-03  ELF 产物经元数据段读取

**Requirement.** 对于 ELF 映像，读取器 SHALL 定位元数据段、按固定记录尺寸切片并解码记录。记录尺寸不匹配 MUST 报为错误，而不是越过段尾读取。不含该段的映像 MUST 得到空模型加一条诊断，而不是失败。

**Rationale.** 定长切片正是未链接目标文件与被 strip 的共享库能被同样读取的原因；错误的尺寸会把相邻数据当作元数据读入。

**Acceptance criteria.**

- **AC-ARTIFACT-03.1** —— **WHEN** 一个由模板构建的目标文件被读取，**THEN** 每条记录的名称、标签、类别、属主、类型、尺寸与偏移均被完整解码。
- **AC-ARTIFACT-03.2** —— **WHEN** 一个不含元数据段的 ELF 被读取，**THEN** 返回空模型并带「无元数据」诊断。
- **AC-ARTIFACT-03.3** —— **WHEN** 记录声明的版本读取器不支持，**THEN** 报告错误诊断并停止解码。

**Evidence.** ELF 需求及其场景；见《Artifact format》。

#### REQ-ARTIFACT-04  归档逐成员展开

**Requirement.** 对于归档，读取器 SHALL 枚举其成员，按各成员自身格式的规则解析每一个被识别的成员，并把该归档表示为一个模块，其子节点为各成员。不带元数据的成员 MUST 被跳过而不报为损坏。两个同名成员 MUST 都保留下来，且标识互不相同。

**Rationale.** 真实的静态库混杂着带元数据的对象与第三方对象。把一个没有元数据的成员当作错误，会使归档在常规情形下无法读取。

**Acceptance criteria.**

- **AC-ARTIFACT-04.1** —— **WHEN** 一个含若干对象的归档被读取，**THEN** 产出一个归档模块，其子节点覆盖每一个成员。
- **AC-ARTIFACT-04.2** —— **WHEN** 一个归档含两个同名成员，**THEN** 两者都有互不相同的标识。

**Evidence.** 归档需求及其场景；见《Artifact format》。

#### REQ-ARTIFACT-05  标识跨运行、跨机器稳定

**Requirement.** 模型中的每一个标识 SHALL 可复现：同一产物解析两次，或在不同目录下解析其副本，MUST 得到相同的标识集合。标识 MUST NOT 含绝对路径、加载地址或随机值。

**Rationale.** 稳定标识是任何比对得以进行的前提 —— 用于回归测试、用于两次构建的差异，或用于一个记住用户展开过什么的查看器。

**Acceptance criteria.**

- **AC-ARTIFACT-05.1** —— **WHEN** 同一产物被检视两次，**THEN** 信号、函数与类型的标识集合相等。
- **AC-ARTIFACT-05.2** —— **WHEN** 同一产物被复制到另一目录后检视，**THEN** 标识集合相等。

**Evidence.** 标识规则及其场景；见《Artifact format》。

#### REQ-ARTIFACT-06  数据链缺失的一半以诊断呈现

**Requirement.** 当一个信号只被写从未被读，或只被读而无声明时，读取器 SHALL 保留该信号，或创建一个明确标记的外部占位，并 MUST 报告一条诊断。它 MUST NOT 静默丢弃该实体或该边。

**Rationale.** 悬空写通常意味着某个模块未被加注解。静默丢弃会让产物看起来完整，而它只是被部分描述。

**Acceptance criteria.**

- **AC-ARTIFACT-06.1** —— **WHEN** 一个信号被写入却从未被读，**THEN** 它保留在模型中，并报告悬空写诊断。
- **AC-ARTIFACT-06.2** —— **WHEN** 某函数体读取了一个声明在被检集合之外的字段，**THEN** 创建外部占位并报告悬空读诊断。

**Evidence.** 悬空数据需求与诊断表；见《Artifact format》。

#### REQ-ARTIFACT-07  规范 JSON 逐字节稳定

**Requirement.** 以 JSON 形式输出的产物模型 SHALL 是规范的：对象键按确定顺序排列，集合型数组按语义键排序，保序数组保持其自然顺序，且不含运行期地址。对同一输入的两次运行 MUST 产出逐字节相同的输出。

**Rationale.** 字节稳定使该 JSON 可用作差异比较目标与测试判据。键序可变的话，每次比对都需要一个归一化器，而归一化器正是真实差异可以藏身之处。

**Acceptance criteria.**

- **AC-ARTIFACT-07.1** —— **WHEN** 同一产物被检视两次并写入两个文件，**THEN** 两个文件逐字节相同。
- **AC-ARTIFACT-07.2** —— **WHEN** 一个不含元数据的产物被检视，**THEN** 运行以成功状态报告信息性载荷与诊断，而非失败。

**Evidence.** 规范 JSON 规则及其场景；见《Artifact format》。

#### REQ-ARTIFACT-08  每一处偏移都有边界

**Requirement.** 读取器 SHALL 对它读取的每一处偏移、长度与表项数做边界检查，并 SHALL 遵守调用方给定的尺寸上限。任何畸形输入 MUST 以诊断或错误呈现，且 MUST NOT 造成越界读取、无界分配或不终止的循环。

**Rationale.** 输入是来自任何地方的二进制，包括被截断的下载和敌意的供应商。信任长度字段的解析器，就是一个会读到相邻内存的解析器。

**Acceptance criteria.**

- **AC-ARTIFACT-08.1** —— **WHEN** 一个在其头部内部被截断的 ELF 被读取，**THEN** 报告与截断相关的诊断，且进程不崩溃。
- **AC-ARTIFACT-08.2** —— **WHEN** 一个产物超过配置的尺寸上限，**THEN** 在加载内容之前即以一条说明性消息拒绝。

**Evidence.** 输入边界需求与尺寸上限场景；见《Artifact format》。

### EXT —— 编辑器集成

#### REQ-EXT-01  产物在只读编辑器中打开

**Requirement.** 扩展 SHALL 为编译产物提供只读编辑器。该编辑器 MUST NOT 提供任何保存、撤销对底层文件的修改或其它写入产物的手段。

**Rationale.** 底层文件是由编译器拥有的构建输出。能写它的编辑器，就是会破坏构建的编辑器。

**Acceptance criteria.**

- **AC-EXT-01.1** —— **WHEN** 一个产物在扩展的编辑器中打开，**THEN** 视图渲染，且不提供该文件的保存入口。
- **AC-EXT-01.2** —— **WHEN** 以编程方式请求编辑已打开的文档，**THEN** 以只读结果拒绝。

**Evidence.** 只读编辑器需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-02  非产物不被接管

**Requirement.** 当某文件的前导字节不匹配任何被识别的格式时，扩展 MUST NOT 接管该文件；它 SHALL 回退到用户本应使用的编辑器。当格式被识别但结构损坏时，扩展 SHALL 打开并展示诊断，而不是失败或阻塞。

**Rationale.** 注册一个二进制查看器意味着会被递上它处理不了的文件。接管它们会在用户本来有图片的位置留下一个空白标签页。

**Acceptance criteria.**

- **AC-EXT-02.1** —— **WHEN** 一个非产物二进制在选定该扩展的情况下打开，**THEN** 扩展视图不出现，默认处理方式生效。
- **AC-EXT-02.2** —— **WHEN** 一个被识别但已损坏的产物被打开，**THEN** 视图出现并展示诊断列表，编辑器保持可用。

**Evidence.** 回退需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-03  一份模型，三个视图

**Requirement.** 编辑器 SHALL 至少提供概览、模块交联与持久化数据三个视图，在同一编辑器实例内可切换，且读取同一份模型。概览 SHALL 报告格式、架构、实体计数、元数据版本与诊断。持久化数据视图 SHALL 把标记为持久化的类型以表呈现，其字段可继续追踪进嵌套类型。

**Rationale.** 读者面对一份陌生二进制时有三个问题：它是什么、它的各部分如何交谈、哪些状态会存活。只回答其中一个，读者就得为其余的去开反汇编器。

**Acceptance criteria.**

- **AC-EXT-03.1** —— **WHEN** 一个产物被打开，**THEN** 概览至少报告格式、架构、模块数、信号数、函数数与诊断列表。
- **AC-EXT-03.2** —— **WHEN** 选中持久化数据视图，**THEN** 标记为持久化的类型以表出现并含其字段，且字段类型在本地定义时可追踪进该类型。

**Evidence.** 三视图需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-04  交联视图遵循既有交互

**Requirement.** 交联视图 SHALL 把编辑器分为流画布与按需展开的层级列表。在用户于列表中选中实体之前，画布 SHALL 不显示任何内容。选中一个信号 SHALL 画出从写入行到读取行的流。选中一个信号 SHALL 另标出引用它的位置，而点击空白 SHALL 清除这些标记且不清除选中状态。过滤器 SHALL 把列表限定为名称、别名或标签命中的实体，并 SHALL 展开通往每个命中项的路径。

**Rationale.** 一次画出全部会得到一张不可读的网。由显式选择驱动画布，使图回答的是用户提出的问题，而不是关于整个程序的问题。

**Acceptance criteria.**

- **AC-EXT-04.1** —— **WHEN** 一个产物被打开且没有任何选中，**THEN** 画布为空。
- **AC-EXT-04.2** —— **WHEN** 选中一个信号，**THEN** 画出从其写入者所在行到其读取者所在行的一条线。
- **AC-EXT-04.3** —— **WHEN** 输入一个过滤词，**THEN** 只保留命中的实体，且它们的路径被展开。
- **AC-EXT-04.4** —— **WHEN** 用户点击画布空白处，**THEN** 引用标记被移除而选中状态保留。

**Evidence.** 交联需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-05  大产物保持可用

**Requirement.** 列表 SHALL 虚拟化，使同一时刻只有视口附近的若干行存在。模型解析 SHALL 在扩展主线程之外执行，使解析期间界面保持响应。超过配置尺寸上限的产物 MUST NOT 被解析；用户 SHALL 被告知命中了哪一个上限，以及该上限可以提高。

**Rationale.** 一万个节点的模型被急切渲染会冻结编辑器，而被冻结的编辑器与一个挂死的产品无法区分，即使解析器本身无恙。

**Acceptance criteria.**

- **AC-EXT-05.1** —— **WHEN** 一个一万节点的模型被滚动，**THEN** 界面保持可交互，且被渲染的行数保持有限。
- **AC-EXT-05.2** —— **WHEN** 一个较大产物被打开，**THEN** 在解析完成之前界面即有响应。
- **AC-EXT-05.3** —— **WHEN** 一个产物超过配置的上限，**THEN** 不尝试解析，且消息点明该上限。

**Evidence.** 大数据量需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-06  视图内容受严格约束

**Requirement.** 视图内容 SHALL 在限制性的内容安全策略下运行，仅允许本地脚本与样式来源，且 MUST NOT 加载远程资源、求值动态代码或插入未净化的标记。源自被检产物的符号名 MUST 以文本形式显示。

**Rationale.** 符号名来自一份用户可能并未构建的二进制。名称是数据，而数据以标记形式进入文档，就是一个只要给字段起个名字即可触达的脚本漏洞。

**Acceptance criteria.**

- **AC-EXT-06.1** —— **WHEN** 任一视图被打开，**THEN** 不发出任何跨源请求。
- **AC-EXT-06.2** —— **WHEN** 产物含一个名称看起来像标记的符号，**THEN** 该名称按字面显示且不运行任何脚本。

**Evidence.** Webview 安全需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-07  产物视图严格只读

**Requirement.** 扩展 MUST NOT 修改产物、MUST NOT 由它生成源码或图文件、MUST NOT 运行它或对其调用任何外部命令。唯一允许的例外是调用随包提供的、其唯一用途为读取产物字节的助手程序。

**Rationale.** 产物路径是一条观察路径。任何把观察变成生成的产物，都需要一个它并不具备的保真度论证。

**Acceptance criteria.**

- **AC-EXT-07.1** —— **WHEN** 一个产物被打开、切换视图、过滤并刷新，**THEN** 该产物的修改时间与内容哈希不变。
- **AC-EXT-07.2** —— **WHEN** 一个可执行产物被打开，**THEN** 它不被启动。

**Evidence.** 只读需求及其场景；见《VS Code 扩展》。

#### REQ-EXT-08  产物可组织进持久化的树

**Requirement.** 扩展 SHALL 提供工作空间范围的树，用户可在其中建立若干根、嵌套分组、把产物挂到任意层级，并给产物一个显示别名。树 SHALL 按工作空间持久化，且不写入仓库。在树中选中产物 SHALL 在编辑器中打开它。不再解析得到的路径 MUST 在树中被报告，且 MUST NOT 被自动移除。

**Rationale.** 一次真实交付会到达几十个相关二进制。逐个按路径重新打开无法扩展，而静默剪掉缺失条目会在一次临时网络故障时摧毁用户的组织。

**Acceptance criteria.**

- **AC-EXT-08.1** —— **WHEN** 树、分组与产物被创建后窗口被重载，**THEN** 该组织关系被保留。
- **AC-EXT-08.2** —— **WHEN** 选中一个产物节点，**THEN** 该产物在扩展的编辑器中打开。
- **AC-EXT-08.3** —— **WHEN** 某产物的文件已不存在，**THEN** 该节点报告该问题并仍留在树中。

**Evidence.** 产物树需求；见《VS Code 扩展》。

#### REQ-EXT-09  交联可导出

**Requirement.** 扩展 SHALL 把选中的交联导出为 `.drawio` 文件、Mermaid 文档与 Markdown 文档。只选中一端的导出 SHALL 要么自动补全另一端，要么在用户允许悬空流时，以各目标格式都能表达的形态明确表示缺失的一端。

**Rationale.** 阅读发生在编辑器内，但受众常在别处 —— 一次设计评审、一份文档、另一个团队的工具。导出是这项观察离开编辑器的唯一途径。

**Acceptance criteria.**

- **AC-EXT-09.1** —— **WHEN** 交联被导出为图文件，**THEN** 该文件在图表编辑器中打开，每个选中的模块侧一个形状，每条选中的流一条边。
- **AC-EXT-09.2** —— **WHEN** 不允许悬空流且只选中一端，**THEN** 对端被包含进导出。
- **AC-EXT-09.3** —— **WHEN** 允许悬空流，**THEN** 导出只含被选中的一侧，并以所选格式支持的方式标记缺失的一端。

**Evidence.** 勾选与导出一节；见《VS Code 扩展》。

#### REQ-EXT-10  分组可配置且在重开后保持

**Requirement.** 扩展 SHALL 允许用户按一个或多个实体属性对列表分组，在每层为每个属性值生成一个桶，为分组命名，并指定某分组为默认。分组 SHALL 持久化在产物旁。当配置的属性在产物中已不存在，或存储的配置无法读取时，视图 SHALL 以降级形式给出提示，且 MUST 保持可用。

**Rationale.** 有用的分组取决于作者如何给系统打标签 —— 按区域、按总线、按设备。那是工具无法推断的知识，而它必须活过下一次启动才值得录入。

**Acceptance criteria.**

- **AC-EXT-10.1** —— **WHEN** 一个分组被配置后重新打开该产物，**THEN** 分组及其名称被恢复。
- **AC-EXT-10.2** —— **WHEN** 某配置的属性在产物中不存在，**THEN** 显示提示，且其余列表正常渲染。
- **AC-EXT-10.3** —— **WHEN** 存储的配置不可读，**THEN** 显示提示，且按默认列表渲染。

**Evidence.** 分组与配置一节；见《VS Code 扩展》。

### PLATFORM —— 可移植性与运行时依赖

#### REQ-PLATFORM-01  命令行工具链无第三方运行时依赖

**Requirement.** 工具 SHALL 仅使用标准库运行在 Node.js 上：安装该工具 MUST NOT 为「源码到图」这条路径要求下载任何第三方运行时依赖。唯一有文档的例外是读取某类产物的元数据所需的外部助手，且该依赖缺失时 SHALL 以诊断呈现而非崩溃。

**Rationale.** 离线构建机或气隙评审工作站无法拉取依赖树。唯一依赖是平台运行时的工具，能在代码被构建的地方运行。

**Acceptance criteria.**

- **AC-PLATFORM-01.1** —— **WHEN** 在一个没有安装任何依赖包的目录中调用工具，**THEN** 源码到图的操作成功。
- **AC-PLATFORM-01.2** —— **WHEN** 某类产物所需的外部助手缺失，**THEN** 诊断点明缺失的运行时，且进程不崩溃。

**Evidence.** 依赖声明与诊断表；见《Implementation》与《Artifact format》。

#### REQ-PLATFORM-02  一个扩展包服务 Windows 与 Linux

**Requirement.** 扩展包 SHALL 平台中立：同一文件 MUST 可安装在 Windows 与 Linux 上，且 MUST NOT 内嵌任何平台相关的运行时。目标机缺少所需运行时的情况下，扩展 SHALL 显示可执行的安装提示，而不是空白视图或无限进行中的状态。

**Rationale.** 按平台发包会使发布矩阵成倍扩大，而本产品的用户常常与发布者处于相反的平台。

**Acceptance criteria.**

- **AC-PLATFORM-02.1** —— **WHEN** 同一包分别安装在 Windows 与 Linux 上，**THEN** 两个安装都能成功打开产物。
- **AC-PLATFORM-02.2** —— **WHEN** 某类产物所需的运行时未被安装，**THEN** 编辑器显示提示，点明该运行时并给出安装途径。

**Evidence.** 前提条件与「没有运行时」两节；见《VS Code 扩展》与《Artifact format》。

#### REQ-PLATFORM-03  单一版本标识整个产品

**Requirement.** 产品中所有包清单 SHALL 在任何时刻都携带同一版本，且当它们不一致时一项检查 SHALL 失败。版本变更 SHALL 一步施加到每一个载体，且产出的包文件名 SHALL 跟随该版本。

**Rationale.** 库与扩展打包在同一个包中一起发布。部分更新会产生一个清单、锁文件与文件名互不一致的包，而这种不一致在用户报告装错版本之前一直不可见。

**Acceptance criteria.**

- **AC-PLATFORM-03.1** —— **WHEN** 比较各版本载体，**THEN** 它们都报告同一版本。
- **AC-PLATFORM-03.2** —— **WHEN** 某个载体被改成不同版本，**THEN** 该检查失败并指出不一致。

**Evidence.** 版本载体表；见《Versioning》。

### VERIFY —— 验证与契约回归

#### REQ-VERIFY-01  四个比对层分离解析、结构、几何与架构

**Requirement.** 一致性测试 SHALL 把解析出的模型、图结构、几何与产出图的架构合法度作为独立的层进行比对。失败 SHALL 点明是哪一层失败。

**Rationale.** 「输出不同」不是缺陷报告。分层是告诉评审者一次差异是解析器回归还是路由改动的关键 —— 两者的影响范围完全不同。

**Acceptance criteria.**

- **AC-VERIFY-01.1** —— **WHEN** 引入一个解析缺陷，**THEN** 模型层比对失败并报告失败层。
- **AC-VERIFY-01.2** —— **WHEN** 引入一个路由缺陷，**THEN** 几何层比对失败而模型层比对通过。

**Evidence.** 比对层表；见《Conformance》。

#### REQ-VERIFY-02  每个公开数字都是测出来的

**Requirement.** 产品文档中发布的任何数字 SHALL 来自实际运行过的命令，且 SHALL 说明测的是什么。尚未测量的数字 MUST 标明未测量，而不是给出估计。

**Rationale.** 一个没人跑过的测试计数或性能数字，是对一个可能从不存在的状态的断言；而它正是读者决定是否相信其余内容时最先依赖的东西。

**Acceptance criteria.**

- **AC-VERIFY-02.1** —— **WHEN** 一个数字被发布，**THEN** 文档说明它是如何测得的。
- **AC-VERIFY-02.2** —— **WHEN** 无可用测量，**THEN** 文档如实说明并指向限制条目，而不是给出一个数字。

**Evidence.** 测量主张及其命令；见《Verification》。

#### REQ-VERIFY-03  被跳过的一致性用例按失败对待

**Requirement.** 一致性运行器 SHALL 在某个金标准用例缺失时失败，而不是跳过它。依赖仓库之外材料的用例 MAY 被跳过，但该跳过 MUST 打印原因。

**Rationale.** 被跳过的测试让未验证的行为看起来已获验证，这严格劣于一个失败的测试，因为没有人会去查它。

**Acceptance criteria.**

- **AC-VERIFY-03.1** —— **WHEN** 某个金标准用例文件缺失，**THEN** 运行失败并点明该用例。
- **AC-VERIFY-03.2** —— **WHEN** 某用例因已说明的外部原因被跳过，**THEN** 该原因与跳过一同打印。

**Evidence.** 运行器需求；见《Conformance》与《Verification》。

#### REQ-VERIFY-04  架构校验器必须能拒绝

**Requirement.** 一致性测试所用的架构校验 SHALL 被证明能够拒绝畸形文档，而不只是接受合法文档。测试 SHALL 包含刻意损坏的输入，并 SHALL 断言每一个都被拒绝。

**Rationale.** 一个什么都通过的校验器与没有校验器无法区分，它会把架构层变成安慰而非检查。

**Acceptance criteria.**

- **AC-VERIFY-04.1** —— **WHEN** 一个违反固定值、含未声明属性、枚举越界或数值字面量畸形的文档被校验，**THEN** 校验失败。

**Evidence.** 变异集及其记录的判定结果；见《Conformance》。

## 4. 横切约束

**性能与规模。**

- **CC-PERF-1** —— 默认布局在最坏情形下 SHALL 对节点数呈二次增长，且该成本 SHALL 作为特征发布，而不是被呈现为一项优化机会。
- **CC-PERF-2** —— 解析 SHALL 对输入尺寸呈线性。
- **CC-PERF-3** —— 大模型 SHALL 按需分片送达编辑器，而不是一次性载荷，使打开一个大产物不会把整个模型序列化进视图。

**边界与畸形输入。**

- **CC-BOUND-1** —— 每一个被解析的长度、偏移与计数 SHALL 在使用前与实际输入尺寸核对。
- **CC-BOUND-2** —— 畸形输入 SHALL 产生一条诊断或错误；它 MUST NOT 产生一个与完整结果无法区分的、看似合理的部分结果。
- **CC-BOUND-3** —— 损坏的图载荷 MUST 大声失败，因为空布局与「图本就没有布局」无法区分。

**安全与只读操作。**

- **CC-SAFE-1** —— 被检产物 SHALL NOT 被加载、执行，或被用于解析依赖。
- **CC-SAFE-2** —— 任何操作 SHALL NOT 修改产物，也 SHALL NOT 由它生成源码或图。
- **CC-SAFE-3** —— 源自被检产物的内容 SHALL 被当作数据，永不当作标记或代码。

**确定性与可复现性。**

- **CC-DET-1** —— 相同输入 SHALL 产出一致的字节输出，不依赖遍历顺序、地址、区域设置或时钟。
- **CC-DET-2** —— 一份已提交的期望输出 SHALL 只因伴随行为变更的有意行动而改变；自行变绿的期望输出是缺陷。

**可移植性。**

- **CC-PORT-1** —— 「源码到图」路径 SHALL 在无第三方运行时依赖的情况下运行。
- **CC-PORT-2** —— 一个扩展包 SHALL 服务所有受支持的平台。
- **CC-PORT-3** —— 运行时缺失 SHALL 产生一条点名补救办法的可执行诊断，而不是静默的空状态。

**可观测性。**

- **CC-OBS-1** —— 一次失败 SHALL 点明失败的是什么：金标准差异的比对层、不可读产物的诊断码、不受支持输入的文件与原因。
- **CC-OBS-2** —— 一条诊断 SHALL 是结果的组成部分，而不是日志上的副作用，使消费方能够呈现它。

## 6. 推迟与排除

以下是真实存在的限制。列在这里，是为了让读者不把愿望误当作承诺。每条都点明它下面的门槛：要把该条移进 §3，必须先成立什么。

| 条目 | 现状 | 为何不作承诺 | 先行条件 |
| :--- | :--- | :--- | :--- |
| 布局开销 | 对节点数呈二次增长；大工程慢 | 尚无空间索引，引入一个只改变速度 —— 那是允许的 —— 但成本曲线是被测量的，不是被回避的 | 一个输出完全相同的空间索引，以及一项显示曲线改善的测量 |
| 离线渲染器的跳线 | 生成文件正确请求；随包渲染器画不出 | 跳线样式是查看器扩展，渲染器所用的开源内核不含它 | 实现该扩展的渲染器，或有文档的替代标记 |
| 离线渲染器的泳道标题位置 | 居中而非左上 | 渲染器限制，不是生成器行为 | 与桌面客户端一致的渲染器 |
| 离线渲染器的文本测量 | 对非拉丁字形为估计值 | 该渲染器无排版引擎，报告字宽为零 | 排版引擎，或字体度量表 |
| SVG 预览的边路由 | 边按中心连线绘制，会穿过图里绕开的形状 | 共享路由需要把边几何暴露为两条路径共用的函数 | 一次不改变其输出的路由器重构 |
| 函数体写回 | 从不执行 | 有意为之：图无法表示逻辑，重建它就是在猜 | 无 —— 这是设计约束，不是缺口 |
| 跨语言符号解析 | 未尝试 | 输入不携带共享类型系统 | 一份横跨两种语言的整程序模型 |
| 命令行中的多页图、图层、标签过滤 | 未接线 | 命令行面按「一次输出一张图」建模 | 中间表示中的页与图层模型 |
| 状态机、时序图、时序（timing）图 | 不支持 | 模型没有状态或次序的概念 | 位于读写流之上的语义层 |
| 几何稳定性 | 冻结于已提交期望输出 | 任何几何改变都会使已记录的布局与手工排版全部失效 | 一条迁移既有布局的路径，而不只是改算法 |
| 本机 PE 与非 CLI 映像 | 仅到头部级处理，并带诊断 | 元数据词汇表是为 CLI 元数据与 C 模板定义的 | 一套本机代码的元数据约定 |
| `.exe`、`.dylib`、`.pdb` 输入 | 不支持 | 在被检格式矩阵之外 | 各格式的读取支持及其元数据约定 |
| 裁剪或单文件发布下的元数据 | 被工具链静默移除 | .NET 裁剪器与单文件打包器会丢弃未被引用的元数据 | 这些工具提供的元数据保留保证 |
| 链接时优化下的元数据 | 不支持 | LTO 会重排与合并段 | 与 LTO 兼容的保留机制 |
| MSVC 目标 | 不支持 | 段与边界符号语义不同于 ELF 工具链 | 等价的记录放置与保留机制 |
| 超长注解值 | 编译期拒绝 | C 记录使用定长内联字符串 | 长度前缀或旁表表示 |
| 未加注解的第三方二进制的解读 | 最多给到格式与符号概览 | 缺少声明层就没有方向与持久化信息 | 一个不制造假边的推断机制 |

## 7. 变更协议

对一条需求、对某条需求点名的行为、或对一份载有实测数字的文档的任何改动，都有既定的后续动作。该表即契约；跳过其对应行的改动是不完整的，无论测试是否通过。

| 如果你改了…… | 你也必须更新…… | 因为…… |
| :--- | :--- | :--- |
| 任何用户可见行为 | 本文档中对应的 REQ 与 AC，且两种语言版本都要 | 本文档是权威；行为改了而需求未改，结果要么是一条未记录的承诺，要么是一次意外 |
| 源码摄取、注解语义或边派生 | 架构文档、注解参考、`.drawio` 格式文档，以及模型层期望输出 | 解析器、词汇表与几何是同一份契约；只改其一会在测试全绿的同时留下一份说谎的文档 |
| 默认布局、路由或任何产出的几何 | `.drawio` 格式文档与几何期望输出 | 已记录的布局与手工排版都钉在该几何上；一次静默改变会破坏每位用户的图 |
| 图的读取行为，包括压缩形态 | `.drawio` 格式文档与拒绝样本 | 丢失布局是本产品最严重的失效，而没有样本它就不会报警 |
| 任何产物读取判定或产出字段 | 程序集产物格式文档与产物测试期望 | 该 JSON 是编辑器与用户自建工具共同消费的公开契约 |
| 任何注解键或其语义 | 注解参考与模板文档，两种语言版本都要 | 一个键只定义一次，却被两个消费方读取；两者分叉即为静默的数据丢失 |
| 任何测试或实测数字 | 验证文档 | 一个不在发布处重述的数字，会成为下一位读者轻信的过期主张 |
| 任何文档 | 另一语言版本中的对应文档 | 只存在于单一语言版本的行为描述是缺陷，不是翻译滞后 |
| 项目总览或文档索引中的主题表 | 这两张表，以及本文档的地位一节（若权威归属变化） | 索引是读者找到契约的途径；漏掉它的索引等于把它藏起来 |
